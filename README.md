# FORTIS: LABYRINTH

**FORTIS GAMES · Roblox · прототип этапа 1 · Luau / Rojo**

Реализован игровой цикл: HUB → портал → первый процедурный этаж → бой со скелетом → сундук → выход → HUB. Сцены и интерфейс создаются кодом через Roblox Instance API; сторонние модели не нужны.

Это исходники и сборки Places. Experience ещё не опубликована. Проверка в Roblox Studio, испытания на реальных Android-устройствах и измерение FPS остаются обязательными перед релизом.

## Что работает в коде

- HUB из чёрного камня и золота, точка появления, портал с ProximityPrompt и сенсорным взаимодействием.
- SOLO: отдельная раскладка из 8–12 комнат с seed, проверкой графа, отсутствием пересечений комнат и маршрутом к выходу.
- Серверный меч, скелет с PathfindingService, фазовые шипы с предупреждением и безопасным обходом.
- Сундук, монеты, счётчик убийств, зелья, завершение этажа после победы, поражение и повторный забег.
- Русский адаптивный HUD, здоровье, цели, схематическая карта, снаряжение и локальная настройка графики.
- Ограничение частоты запросов; сервер определяет урон, цель, дистанцию, награды и состояние забега.
- Два production-проекта Places: TeleportAsync, ReserveServerAsync и серверный одноразовый допуск через MemoryStore, привязанный к игроку и резервному серверу.
- Начальная схема профиля: монеты, убийства, смерти, зелья и прохождение. UpdateAsync, блокировка сессии, повторные попытки, автосохранение и ограниченный журнал наград.

В Studio сохранения всегда временные. В опубликованных серверах Config.EnablePersistence включает DataStore; ошибка загрузки блокирует вход, а не заменяет профиль пустыми данными. Перед телепортом профиль сохраняется и освобождается, при неудаче загружается снова.

## Быстрый запуск

1. Скачать `FORTIS-Preview.rbxlx` из артефакта GitHub Actions или локальной папки `dist/`.
2. На Windows/macOS открыть файл в Roblox Studio и нажать **Play**.
3. Войти через портал или кнопку HUD, победить скелета, найти выход и вернуться в HUB.

Preview работает без Place ID и без облачных API сохранения. При многопользовательском тесте каждый игрок получает свой SOLO-этаж. Это режим разработки; рабочие HUB и Dungeon следует публиковать из отдельных сборок.

На Android нет поддерживаемой Roblox Studio. Владелец может работать с GitHub и Creator Dashboard с телефона; для первого открытия/публикации этих файлов потребуется Studio на поддерживаемом компьютере или доверенный исполнитель с правами на Experience. Исходники вручную писать не требуется. Пошаговый порядок — [docs/publishing.md](docs/publishing.md).

## Проверки и сборка

Версии инструментов закреплены в `rokit.toml`. После установки Rokit: `rokit install`. Можно также скачать официальные бинарники соответствующих версий в `tools/bin/`.

```sh
python3 scripts/check_project.py
lune run scripts/test.luau
stylua --check src tests scripts
mkdir -p dist
rojo build default.project.json -o dist/FORTIS-Preview.rbxlx
rojo build hub.project.json -o dist/FORTIS-Hub.rbxlx
rojo build dungeon.project.json -o dist/FORTIS-Dungeon.rbxlx
```

GitHub Actions выполняет доступные проверки и прикладывает собранные Places. Они не заменяют сервер Roblox, физику, Pathfinding, реальные DataStore/Teleport и тестирование UI на телефоне. Фактические результаты этой сессии — [docs/validation.md](docs/validation.md).

| `src/shared/` | Конфигурация, чистые правила, генератор и валидатор |

## Границы этапа 1

Играбелен только этаж 1 и только SOLO. Чистый генератор уже поддерживает диапазоны количества комнат всех 25 этажей; тематические зоны, остальные ловушки, боссы и переходы между этажами ещё не реализованы.

CO-OP, HARDCORE, полное RPG-снаряжение, магазин, платежи, VIP Overlord, глобальные рейтинги, 20 титулов, Зал Славы и админ-панель относятся к следующим этапам. Обозначенные в HUB места будущих систем — декорации с явной маркировкой этапа. В прототипе нет покупок Robux, ProcessReceipt или платных преимуществ.

Цель — 30 FPS на согласованных Android-устройствах; измерений на устройствах пока нет. StreamingEnabled, атомарная загрузка этажа, ограниченное количество деталей, отсутствие теней у локальных источников света и настройка графики создают основу для дальнейшей оптимизации.
